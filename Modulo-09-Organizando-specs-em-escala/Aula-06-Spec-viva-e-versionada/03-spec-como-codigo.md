# A spec como código

Documentos Markdown **no repositório**, com o mesmo fluxo do código:

1. **Branch**: `spec/notificacoes-24h`.
2. **Mudança** na spec.
3. **Pull Request**: revisão e discussão.
4. **Aprovação** por quem decide.
5. **Merge**: a spec nova passa a valer.

O **histórico** do Git responde *"quem, quando e por quê"* (`git log docs/product/notificacoes.md`).
